# Evidence pipeline v2.1 implementation status

This is an incremental implementation. It does not yet claim the full v2.1 design or measured latency/accuracy improvements.

## Available behavior

- Course correction uses at most two active calls and an admitted/uncommitted window of four, with source-order checkpoint commits.
- Both correction and derived subtitle summaries use a persistent physical-attempt ledger. Policy v1 caps one stable job at 256 physical requests across retries, JSON repair and resume. Tokens and provider billing are unknown; byte/count guards are not monetary guarantees. Complete responses without usage spend the attempt cap; dispatched errors, 429 and unconfirmed results retain UNKNOWN liability. Such UNKNOWN calls do not automatically retry. There is currently no user-facing manual release/settlement action; the app must not imply a recovery button exists.
- Stable correction identity includes lecture/source fingerprint, exact batch rows, the exact request builder's endpoint/body digest (including actual selected images/context and model parameters), JSON repair policy and a versioned correction recipe. Validated successes are cached separately from committed progress. Resume can explicitly adopt matching successes; source/request/recipe/epoch mismatch prevents adoption. One entry is limited to 4 MiB and a job's live success cache to 64 MiB.
- A cross-process OS lease prevents live task takeover. Process death releases it. SQLite is the execution-generation authority; generation rollover and guarded local task/publication mutations share a write serialization point.
- New subtitle summary recipe v2 uses half-open Unicode codepoint core spans. Subcue text inherits the full parent cue time; no word timing is invented. Observer protocol v3 records explicit processing receipts independently of cards. Complete with zero cards is valid; insufficiency marks the published summary as partial. Processing coverage is not semantic completeness.
- Recipe v2 summaries now share the correction scheduler's two-active/four-admitted window. Transport/repair transitions and format references are independent per chunk; the global immutable event chain is serialized. Parent completion requires every chunk terminal, and publication verifies chunk points in source order even when responses arrive out of order.
- Summary successful payloads persist before their local validated event, binding exact request/source/recipe/core identity and the original format receipt. Resume records epoch-fenced adoption and reuses original HTTP evidence; a staged payload may complete only its missing local validated link. Missing, damaged or incomplete attempted evidence never falls back to a new HTTP request. Bounded uncancelled local cleanup protects a completed payload from sibling cancellation; root cancellation can still fence the observer link, which is recoverable from durable payload. Error-return fault fixtures cover both sides of that link, not process-kill validation.
- Existing frozen recipe v1 tasks continue using their original prompt, cue chunking and observer protocol, including uncalled items after a completed item. Old v1/v2 audit interpretation remains supported.
- Nonstream and stream responses have an 8 MiB cumulative wire-byte limit, JSON depth64 and string1MiB limits before JSON allocation. SSE completion checks remain required. Read errors do not expose transport details.

## Remaining work

Optional semantic-boundary proposals with deterministic fallback, an independent halo ablation control, product-facing cache-revocation/explicit reauthorization operations and benchmark ablations remain pending. The internal revoke/tombstone transaction is tested, but is not yet a product action. Cancellation is not permanent revocation. No token hard limit is asserted without a verified tokenizer/usage adapter.

## Experimental global organization and risk review

Default remains recipe v2. New tasks opt into recipe v3 only when the operator sets `ZYNOTE_SUMMARY_EXPERIMENTAL_GLOBAL=1`; existing frozen v3 tasks resume with that switch off. There is no settings UI for this experiment.

Content-addressed tree pages bind source, recipe, generation, epoch, per-chunk ordinal and every leaf disposition. Limits are fanout4, depth8, nodes8192, page256KiB, card64KiB and builder32MiB. A stable job also conservatively reserves at most64MiB for tree/global blobs across generations before filesystem publication; a crash retains the reservation. Final encoded points are limited to16MiB.

Independent reduce and original-span risk-review calls use protocol4 stage chains, the same persistent physical-attempt guard, exact-input success caches and durable adoption. A reduce must explicitly consume or omit each child. Leaf-page review receives the full original core text and up to eight selected cards. This is selected risk review, not semantic completeness. Unsupported/uncertain conclusions carry explicit per-point states in Markdown, JSON and SVG. Unreviewed parent model prose is suppressed; supported leaf summaries remain available in source order. Leaf-unreviewed and parent-unreviewed counts are separate, and any unreviewed parent makes the result partial. Missing or corrupt attempted evidence never automatically replays HTTP.

Synthetic service tests cover interleaved chunk calls, independent stage payload/format recovery, budget-limited publication and three-page parent reduction. Fault injection returns errors; it is not a process-kill experiment. Full relevant Go packages pass race checks.

Two exploratory real-provider runs used official `https://api.deepseek.com`, requested alias `deepseek-flash`, temperature0 and max_tokens8192. The actual server snapshot and token/billing usage were not captured. On a public one-chunk source, legacy/v2/v3 took15.286/24.483/27.302 seconds (1/1/3 requests). On the same public full-course source with832 cues and3 chunks, they took28.981/22.950/58.673 seconds (3/3/10 requests); v3 recorded7 global stages and partial status because the parent was unreviewed. These are one-run observations with different output points, not a stable speedup, p95 or quality non-inferiority result. The single-chunk v2 run was slower than legacy.
