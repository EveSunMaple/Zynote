# Bilibili 会话、网页浏览与视频学习接线

## 已确认设计
Go 是扫码、加密 Cookie 档案与 API 鉴权 owner；Electron 仅承载系统加密与隔离网页会话，Rust 原生 PDF/ASR/向量职责保持。新增浏览窗口不向远程网页暴露 preload/Node/应用 IPC。仅本地应用可发起浏览，用户在原生菜单选择当前视频导入视频摘要、字幕或课件。使用现有视频摘要页面和 video-ppt:summary，保留引用校验与课程保存。

## 实施和验收
1. 修复凭据载入失败被缓存、Cookie scope 和保存失败吞错，验证扫码成功必须包含必要 Cookie。
2. 统一所有字幕/分集调用使用当前 Resources 的鉴权 HTTP 客户端，禁止跨站或重定向泄露 Cookie。
3. 视频学习下载复用 Go 原生媒体 catalog/transfer/mux，不再依赖 SnapAny；保留任务取消与完整文件探测。
4. 浏览窗口使用 persist:zynote-bilibili，启动时从 Go 内部桥恢复 Cookie，退出清除并关闭窗口。网页不获取应用桥，当前地址必须验证后才能导入。
5. 回归扫码/过期/重启读取/失效/登出/加密错误、跨站请求、字幕与分P、网页导入路由及原有笔记格式。运行 TS、Go、Rust 门禁，实际扫码和真实模型摘要须与受控测试分开记录。

## 范围
不导入 BiliSum 凭据或私有源码；不宣称永不过期，不保证突破平台风控或受限内容访问。网页会话在打开时由 Go 档案同步；浏览页面中自行重新登录需在账号设置重新扫码以统一 API 身份。

## 使用方式
在设置的 B站账号页扫码并手机确认；在 B站资源或账号页点“打开/浏览 B站”。Windows/Linux 可用窗口菜单，macOS 或其他系统可右键页面，从 Zynote 原生菜单选择当前视频导入。分P会保留，视频摘要沿用原页面、课程、四种模式与导出格式；默认生成详细摘要，无站内字幕时走现有本地转写。登录过期、网络错误和拒绝访问直接显示失败，不把它们伪装成“无字幕”并启动下载。

远程网页没有 preload 和应用 IPC；凭据仅在 Go 与 Electron 主进程之间传递。每次打开窗口先清理独立分区，再从加密 owner 恢复快照；扫码切换身份成功或退出账号会关闭并清空旧窗口。会话打开/清理串行执行，防止退出与打开交错。网页内自行重新登录不会写回 Go owner，应从账号页扫码统一身份。
